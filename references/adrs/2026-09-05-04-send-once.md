# ADR-035: Send each effect once and expose failures to the Agentloop

- Decision date: 2026-09-05
- Status: Accepted
- Compiled: 2026-09-05

## Context

A timeout, cancellation, disconnect, or missing remote receipt does not prove an external action did not happen. Automatic retry or target fallback can duplicate side effects. Operational logs alone cannot inform the loop or model of a recoverable Environment failure.

## Decision

Durably commit an effect’s started record before dispatch, send it once, and commit the terminal or unknown outcome before returning it to the Agentloop. Do not automatically retry model, Tool, or Environment effects. Expose actionable failures as Events; use the common ctx.emit operation for extension Events. The loop decides whether to disclose an observation to the model or request a new action.

## Alternatives considered

Exactly-once execution cannot be inferred from a local journal. A retry engine, acceptance protocol, delivery counters, or silent target substitution would add unsupported guarantees and policy. Best-effort telemetry remains separate under [ADR-015: Keep telemetry bounded and best effort, and use cursors for durable consumers](2026-08-31-01-telemetry.md).

## Consequences

A retry chosen by a loop is a new explicitly recorded effect. Cancellation may stop waiting while a remote action continues, so its outcome can remain unknown. Reserved system/private Event names and per-turn event limits protect the canonical feed. Direct guest HTTP/WASI I/O is governed by the Environment capability policy; only Brain-mediated effects receive Brain’s effect record semantics.
