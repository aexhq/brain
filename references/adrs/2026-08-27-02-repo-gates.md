# ADR-008: Keep Brain documentation and release verification with the product

- Decision date: 2026-08-27
- Status: Accepted
- Compiled: 2026-09-05

## Context

Problems in packaged images and SDK consumers were being discovered too far downstream. Handwritten API descriptions could also drift from implementation.

## Decision

Keep user documentation beside Brain code and verify real packaged/server behavior in Brain’s own CI and release workflow. Generate the API reference from the contract. Exercise the SDK and HTTP paths, worker execution, and images before promotion. Brain uses the MIT license.

## Alternatives considered

Only building an image or checking startup does not establish working session behavior. Deferring verification to a consuming platform lengthens the feedback loop. Hand-maintained API reference pages duplicate contract work.

## Consequences

CONTRIBUTING.md and the workflow files specify executable checks. [ADR-031: Generate public contracts from Rust types and route annotations](2026-09-04-09-rust-contracts.md) establishes the eventual source direction, and [ADR-039: Keep performance claims historical until representative baselines are rebuilt](2026-09-05-08-benchmark-policy.md) distinguishes correctness/release gates from optional performance diagnostics. This ADR records product-local verification; it does not prescribe another repository’s release process.
