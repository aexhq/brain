# ADR-029: Declare machine-readable Events and failures once

- Decision date: 2026-09-04
- Status: Accepted
- Compiled: 2026-09-05

## Context

Clients and Agentloops needed to interpret failures without parsing prose. Independently written strings and inconsistent failure payloads allowed producers and consumers to drift.

## Decision

Declare system record kinds, failure codes, and API error codes in brain_protocol::codes and render the public code catalogue from it. Use a common typed Failure shape with code, message, retryable, and ambiguous. Derive runtime error codes from typed variants rather than message text.

## Alternatives considered

A descriptive log message is useful for operators but not a stable machine interface. Keeping unused codes for hypothetical callers creates a misleading contract.

## Consequences

Extensions can append their own Events without impersonating reserved system/private record names. Retryable describes a failure; it does not authorize the runtime to retry it. Actionable failures remain visible to the Agentloop under [ADR-035: Send each effect once and expose failures to the Agentloop](2026-09-05-04-send-once.md).
