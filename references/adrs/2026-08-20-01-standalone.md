# ADR-001: Make Brain an independent runtime with injected execution ports

- Decision date: 2026-08-20
- Status: Accepted
- Compiled: 2026-09-05

## Context

The first Brain implementation combined session execution with a particular hosted product, tool set, and infrastructure. An independent consumer needed to run and extend Brain without adopting that deployment.

## Decision

Ship a runnable server, a public HTTP/SSE interface, and an SDK, while keeping the session library independent of a particular cloud or Environment implementation. Inject execution and storage dependencies. Official extensions consume the same public contracts as third-party implementations.

## Alternatives considered

Keeping a product-specific runtime was simpler for the first deployment but made the supposedly reusable core depend on its consumer. A library alone would omit the standalone service explicitly requested by the user.

## Consequences

The server is the composition root. Product policy and infrastructure stay with consumers. The exact per-session library boundary was completed in [ADR-021: Make the core runtime one session and let the server manage sessions](2026-09-02-04-session-runtime.md); the current meaning of distributed execution and the MVP limits are recorded in [ADR-037: Release execution at turn boundaries and prepare artifacts before creation](2026-09-05-06-ephemeral.md).
