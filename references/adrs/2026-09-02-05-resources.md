# ADR-022: Let Environments execute implementations using their own platform APIs

- Decision date: 2026-09-02
- Status: Accepted
- Compiled: 2026-09-05

## Context

A closed set of capability handles and Brain-specific fs/net/page wrappers made every new resource expand the extension framework. Tool authors needed familiar platform APIs and dependencies inside the execution environment.

## Decision

Tools declare implementation descriptors and resource needs; Environments declare the resources they provide at attachment. Brain validates the match and routes execution. The actual filesystem, subprocess, HTTP, DOM, secrets, and resource policy are implemented and enforced at the Environment boundary.

## Alternatives considered

Translating every API through Brain creates an ever-growing private platform abstraction. Inferring a language runtime or installing packages on demand sacrifices explicit placement and reproducible preparation. Opaque descriptors let the selected driver own non-Component execution.

## Consequences

The September 2 program/runtimes schema was later simplified by [ADR-033: Distinguish resident Tools from explicitly placed extensions](2026-09-05-02-placement.md): Brain itself accepts raw Components for native execution and otherwise leaves implementation descriptors to drivers. Matching a resource name is admission, not security enforcement. Runtime and dependencies must be prepared by the selected execution path.
