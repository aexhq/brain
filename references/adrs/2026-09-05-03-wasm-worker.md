# ADR-034: Run native Components in a separate capability-restricted Wasmtime worker

- Decision date: 2026-09-05
- Status: Accepted
- Compiled: 2026-09-05

Amended by [ADR-044](2026-09-06-03-sessions-and-brain-env.md): brain-env owns the built-in
Environment and a pool of multiple worker processes; fresh invocation state remains.

## Context

Brain needed one small native execution option with useful HTTP/filesystem access, without bundling source runtimes or provisioning a VM per invocation. Long I/O waits had to remain valid while runaway guest work was bounded.

## Decision

Run prebuilt Components in a separate Wasmtime worker with shared engine and compiled-code cache, but a fresh Store and instance per invocation. Start without ambient environment, stdio, or network. Allow only requested HTTP(S) targets, named secrets, and scratch/workspace roots that the deployment also grants. Apply memory limits and guest fuel, independent of turn wall time, and release the Store on cancellation or lost worker-client connection.

## Alternatives considered

A native callback inside Brain grants too much authority to customer code. An OS process/container per call adds startup work without supplying the desired Component contract. A native MicroVM default would duplicate an external Environment option. Wasmer/core-Wasm alternatives are recorded in [ADR-005: Keep WIT Components and use Wasmtime for the native runtime](2026-08-26-01-runtime-choice.md).

## Consequences

A request cannot grant itself Brain process secrets, host network, or writable storage. Wasm/process isolation is not a claim of VM-grade hostile-tenant containment or fairness. The initial September 5 decision described eight shared Stores; [ADR-037: Release execution at turn boundaries and prepare artifacts before creation](2026-09-05-06-ephemeral.md) subsequently separates parent and Tool permits to prevent nested-dispatch deadlock. Fixed implementation bounds belong in configuration/code, not a permanent architecture promise. Optional stronger isolation remains [ADR-038: Defer dynamic placement, workflow durability, and advanced tenancy policy](2026-09-05-07-roadmap-boundary.md).
