# ADR-037: Release execution at turn boundaries and prepare artifacts before creation

- Decision date: 2026-09-05
- Status: Accepted
- Compiled: 2026-09-05

Amended by [ADR-044](2026-09-06-03-sessions-and-brain-env.md): callers decide Environment
lifetime and request lifecycle operations; Environments implement them without owning TTL
policy. Fresh guest instances and retained Environment resources remain distinct.

Supersedes: [ADR-027: Suspend idle session actors after an idle TTL](2026-09-04-05-idle-ttl.md).

## Context

Brain multiplexes many conversations on one machine; an idle turn may be the last turn forever. Eager startup recovery, retained actors, repeated compilation, and one shared parent/Tool permit pool made memory, readiness, or nested dispatch depend on unrelated sessions.

## Decision

Release the actor and cached history state after create/turn completion by default. Optional idle TTL retains execution, with explicit zero retaining it indefinitely. Read transcript and Events without activation; load sessions on demand. Cache admitted compiled/prelinked code separately from creation and instantiate fresh invocation state. Give parent turns and native Tools separate permits. Use a checksummed disposable checkpoint to accelerate reopen, retaining the canonical journal as truth.

## Alternatives considered

Retaining session instances optimizes a previous turn shape at the cost of idle memory. Opening every journal at boot makes cold readiness history-dependent. A single permit pool can deadlock when every parent waits for a Tool that needs the same exhausted pool. Suspending Wasm in the middle of model/tool waits might save more memory but needs measured continuation costs and is deferred.

## Consequences

Transcript and returned JSON slots are durable state; heaps, stacks, sockets, and Environment files are not. A checkpoint avoids decoding unchanged history but its index/transcript still grow with history; this is not constant-time activation. Providers own lazy allocation, TTL, resource loss, and cleanup. Expired files need not be restored, and reloaded resource status is unknown until observed. Live subscriptions are per session; historical telemetry still needs a sink. “Distributed” means tools across Environments, not clustered journal ownership.
