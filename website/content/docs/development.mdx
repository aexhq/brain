This guide is for contributors. It covers how to set up a local development environment for Brain, run the full verification suite, regenerate the OpenAPI document and SDK wire types, preview the documentation site, and how CI tests and publishes each release.

## Prerequisites

- **Go `1.26+`** (`go.mod` declares `go 1.26.0`)
- **Node.js `24+`** and `npm`

Python 3.11+ must also be available as `python` for the sandbox execution fixture.

## 1. Install workspace dependencies

Install the locked dependencies for the three harness runners, TypeScript SDK, sandbox and browser services, and documentation site:

```sh
node scripts/setup.mjs
```

The script installs each workspace lockfile and Chromium for the browser journeys. On Linux, install Chromium's OS dependencies with `npm --prefix tools/browser exec -- playwright install-deps chromium`.

To build BrainServer from the repository root, run:

```sh
npm run build
```

This builds the Pi harness, TypeScript client, and Go executable together and writes npm archives to `dist/server/`. Use `npm run build -- --all-platforms` to cross-compile all six supported platforms.

## 2. Run all checks

Run `node scripts/check.mjs` before you commit:

```sh
node scripts/check.mjs
```

It runs these steps in order and stops at the first failure:

1. `go run ./services/brain/cmd/generate -check` and `node sdks/typescript/scripts/generate.mjs --check`: verify the service OpenAPI contract, runtime protocol schema and TypeScript declarations against their Go sources.
2. `npm --prefix runtimes/pi run build`: compiles Pi; Codex and OpenCode build commands validate their JavaScript entry points.
3. `npm --prefix sdks/typescript run build`: compiles the TypeScript SDK (`sdks/typescript/dist/`).
4. `node scripts/package-sdks.mjs`: packs and installs the npm package in an isolated consumer, then runs client tests, CLI help and a strict TypeScript consumer check.
   The suite also runs `npm run build` and `node --test tests/server-package.test.mjs`. These build the server, Pi harness, and client together, install their npm archives outside the checkout, and exercise model calls, application tools, restart recovery, startup failures, and parent-exit cleanup. Linux CI cross-compiles the six platform executables into the tested server release artifact.
5. `go test -count=1 ./...`: runs all Go unit and integration tests across the services, runtimes and shared packages.
6. `go vet ./...`: runs Go static analysis.
7. `npm --prefix runtimes/pi test`: runs the Pi runner unit and integration tests against a local recording provider.
8. `npm --prefix sdks/typescript test`: runs the TypeScript SDK test suite.
9. The sandbox and browser services run their test suites, including real Chromium network and cancellation checks.
10. The three suites in `tests/journeys/` run the [end-to-end journeys](https://github.com/aexhq/brain/blob/main/tests/journeys/README.md) through installed clients and all three native harnesses, including browser attachment and the remote service.
11. `node --test tests/platforms.test.mjs`: validates the platform deployment examples under `examples/platforms/`.
12. `node --test tests/registry-artifacts.test.mjs`: tests the SDK release workflow's admission checks and registry publication, including partial uploads, registry outages, and version reuse.
13. `npm --prefix website run build`: generates the derived docs pages and builds the static Next.js / Fumadocs export.
14. `npm --prefix website test`: runs `website/scripts/site.test.mjs`.

## 3. Regenerate contracts and docs

When you edit Go route declarations, wire structs, or shared Markdown sources, regenerate the derived artifacts:

```sh
# Regenerate services/brain/api/openapi.json, runtimes/pi/src/generated.ts,
# sdks/typescript/src/generated.ts, and runtimes/host/protocol.json
go run ./services/brain/cmd/generate
node sdks/typescript/scripts/generate.mjs

# Regenerate website/content/docs/** generated pages and website/public/openapi.json
npm --prefix website run generate
```

## 4. Preview the documentation site

Regenerate the derived pages and start the local Next.js development server:

```sh
npm --prefix website run dev
```

Open `http://127.0.0.1:3000/docs`. To test the static production export locally, build it, run the site tests, and serve `website/out` on port 3000:

```sh
npm --prefix website run build
npm --prefix website test
npm --prefix website start
```

## Where to edit what

Don't hand-edit generated files (`services/brain/api/openapi.json`, `runtimes/pi/src/generated.ts`, `sdks/typescript/src/generated.ts`, `website/public/openapi.json`, or generated MDX pages). Edit the source of truth and run the corresponding generator:

| Area | Source of truth | Regenerate with |
| --- | --- | --- |
| HTTP routes, summaries, and wire types | `services/brain/internal/http/contract.go` & `services/brain/api/types.go` | `go run ./services/brain/cmd/generate`, `node sdks/typescript/scripts/generate.mjs`, then `npm --prefix website run generate` |
| Harness & storage Go interfaces | `runtimes/host/harness.go`, `runtimes/host/process.go`, `services/brain/internal/archive/*.go` | `npm --prefix website run generate` |
| Model catalog | Pinned `@earendil-works/pi-coding-agent` in `runtimes/pi/package.json` (`runtimes/pi/scripts/model-catalog.mjs`) | `npm --prefix website run generate` |
| Persistence guide | `docs/running-persistence.md` | `npm --prefix website run generate` |
| Local tools walkthrough | `examples/tools/README.md` | `npm --prefix website run generate` |
| Sandbox service guide | `tools/sandbox/README.md` | `npm --prefix website run generate` |
| Resource service guide | `tools/resources/README.md` | `npm --prefix website run generate` |
| Platform examples guide | `examples/platforms/README.md` | `npm --prefix website run generate` |
| Roadmap | `docs/roadmap.md` | `npm --prefix website run generate` |
| Docs pages & guides | `website/content/docs/**/*.mdx` | `npm --prefix website run build` |

Follow the [writing guide](https://github.com/aexhq/brain/blob/main/docs/writing.md) when you change the README, a docs page, or a shared Markdown source.

## Repository ownership

- `services/<service>/cmd/<program>/` contains Go executable startup and configuration. Each service owns its `api/` and private `internal/` packages.
- `services/brain/api/openapi.json` is generated from Brain's Go types and route declarations using Huma schemas. `openapi-typescript` generates the TypeScript contract; `openapi-fetch` implements typed SDK requests.
- `cli/` uses Commander and the public SDK. Its build helper lives in `cli/scripts/`; repository packaging and verification live in root `scripts/`.
- `runtimes/` owns agent integrations and runnable payloads. The generic Sandbox service owns their environments and processes. See the [runtime layout](https://github.com/aexhq/brain/blob/main/runtimes/README.md).
- `internal/dirlock/` is the private cross-platform directory ownership lock shared by local storage users.

## CI and releases

The [CI workflow](https://github.com/aexhq/brain/blob/main/.github/workflows/ci.yml) runs on every push and pull request, and weekly:

- **Checks:** `node scripts/check.mjs` on Linux and Windows. On Linux, the job also builds the Brain and sandbox tool images and smoke-tests both containers.
- **Race detection:** `go test -race ./...` on Linux.
- **PostgreSQL:** the session index tests against a real PostgreSQL server.
- **Docs:** builds the site for its GitHub Pages path and runs the site tests.
- **CodeQL:** code scanning for Go, JavaScript/TypeScript, Python, and GitHub Actions.

Nothing publishes unless every job passes. After that, each push to `main`:

1. Publishes the tested images to `ghcr.io/aexhq/brain` and `ghcr.io/aexhq/brain-sandbox-tools`, tagged `sha-<commit>` and `main`, with build provenance attestations.
2. Deploys the tested docs site to GitHub Pages, then smoke-tests the published site.
3. Starts the SDK release, which publishes the SDK archives tested on Linux to npm through registry trusted publishing, without rebuilding them, and attaches the same archives to a GitHub release.

SDK 2.1.0 is the client for the current server and replaces the predecessor's 0.x API. The server's routes and local state have no versioning or compatibility layer, so pin production images by digest and use the SDK version that matches your server commit. [SDK delivery](https://github.com/aexhq/brain/blob/main/docs/sdk-releases.md) covers versioning, the release workflow, and registry setup.
