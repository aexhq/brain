# ADR 0001 Local first ephemeral session server

Status: Accepted direction; implementation pending  
Date: 2026-10-15

Brain is a standalone agent server for developers building agent platforms for their users. It provides fast session execution and external integrations. The surrounding platform owns placement, cross-instance session ownership, autoscaling, and failover. Losing state that has not reached external storage when a machine dies is acceptable.

We will build a small Go server, initially with a Pi adapter in a thin TypeScript process. The following decisions define its boundaries:

1. **Small public model.** Developers create sessions and send/read events using familiar messages, tool calls/results, and session status. No Environment, job, effect, approval, or worker entity is required in the public model. Use one current contract generated from code; add a concept only for an implemented need.
2. **Session execution.** Brain owns lifecycle, authorization, transport to distributed tools, and persistence. Harnesses own model calls, context selection, compaction, scheduling, and continuation after tool results. Each instance permits one active execution owner per session. Harness and tenant identity stay fixed. Model/effort/instructions and tool definitions/bindings are frozen at creation for launch; credentials may rotate and access may be revoked. Configuration freeze is a launch policy, not an intrinsic property of a session or a provider cache requirement. The [API plan](../plans/05-api-and-sdks.md#future-configuration-updates-proposed) proposes later updates through the same configuration shape at tested execution boundaries. Unsupported requested behavior fails explicitly.
3. **Local state and recovery.** SQLite stores metadata; files store append-only events and harness-owned native state. Resume uses usable local state first, then a configured external store; reassignment explicitly restores external state. Missing or invalid state is an error, never an implicit new session. Restore native context as well as visible history, independently of provider prompt-cache availability. Preserve a stable prefix where Brain controls it; do not hash growing prompts on each turn. Rewind changes the selected history tail through a supported harness operation and does not undo external effects.
4. **Optional external persistence.** Add asynchronous transcript/checkpoint storage in S3 and R2, plus an external SQL metadata adapter. Write immutable segments and publish checkpoint references after their dependencies are uploaded. Expose synchronization progress and explicit flush. Local acceptance does not promise external durability; recovery starts at the latest complete checkpoint and may omit the unsynchronized tail. Avoid copying the whole growing transcript or native history after every turn.
5. **Distributed tools.** Support language-neutral HTTP/SSE tools, then MCP through an adapter. All agent-facing tool implementations, including approvals and compute/resource management, live outside Brain. Brain authenticates and bounds transport; the tool owns execution, approval policy, external jobs, and cleanup. A normal tool return completes that invocation. A tool may wait or return a job handle; the harness decides when the model continues. Self-inspection uses session-scoped access to Brain's API. Brain does not replay tool invocations; any retry policy belongs to the tool service with its own idempotency guarantees.
6. **Distinct errors.** Tool failures, denial, timeout, and unknown remote outcomes become tool results for the harness/model. A Brain failure that prevents trustworthy execution, such as a failed local append or broken runner protocol, stops the affected execution and is reported separately. Invalid client requests are rejected without terminating an otherwise healthy session. No tool payload can impersonate a Brain control event.
7. **Bounded work and observability.** Use small in-process workers for flushing and transient storage retries, with count/byte limits, backpressure, and a deadline-bound shutdown drain. Keep control/completion paths responsive during tool waits. Transport keepalives and health checks must not enter model context or trigger inference. Disable harness cache warming; Brain never wakes a model merely to keep it active or poll a quiet tool. Include structured Go logs and OpenTelemetry from R0; bounded exporters must not stall execution. No broker, durable job framework, or mandatory external database is required.
8. **Clean breaks by default.** No Brain API, protocol, or saved-format versioning scheme, backward-compatibility layer, migration framework, deprecated alias, or compatibility negotiation. This applies to every release unless explicitly overridden. Change server, adapters, generated clients, examples, and tests together. Pin upstream dependencies for reproducible builds; that does not promise cross-release restore. Unreadable state fails explicitly and is never silently replaced or deleted.

This keeps session coordination and working state local, with tools executed externally. It accepts tail loss and eventual external consistency while retaining explicit errors and overload control. Initial recovery guarantees apply at completed, saved turn boundaries; stronger recovery is an adapter capability to prove through tests.

Start with one harness and local storage. Add dependencies and abstractions only for an implemented requirement. Protocol schemas, SQL, and implementation types remain the sources of truth; generate derived contracts where practical. The [roadmap](../roadmap.md) defines release scope; the [implementation index](../implementation-plan.md) links delivery and verification plans.
