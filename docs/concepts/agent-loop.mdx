---
title: Agentloop
description: The placed WebAssembly Component that owns a turn's policy.
---

An Agentloop decides how one user message becomes a completed turn. Brain owns mechanism: the
journal, model binding, Tool catalogue, effect dispatch, deadlines, and cancellation. The
Agentloop owns policy: prompts, context selection, compaction, Tool sequencing, and the final
transcript and extension state.

## Bind a Component

Brain accepts an already-built WebAssembly Component. It does not compile TypeScript or another
source language.

```ts
import { agentloop, brainWasm, component } from "@aexhq/brain";
import { z } from "zod";

const assistant = agentloop({
  options: z.object({ compactAt: z.number().min(0).max(1) }),
  implementation: component(new URL("./assistant.wasm", import.meta.url)),
});

const bound = assistant({
  env: brainWasm({ network: { allow: ["api.example.com"] } }),
  compactAt: 0.8,
});
```

`component(...)` accepts a `URL` or `Uint8Array`. The client reads the raw bytes, admits them by
content identity, and then creates the session with that identity, the parsed options, and the
selected Environment. Every Agentloop factory is placed with `{ env, ...options }`.

## The Component contract

The source of truth is [`contracts/agentloop/v1/agentloop.wit`](https://github.com/aexhq/brain/blob/main/contracts/agentloop/v1/agentloop.wit).
The Component exports one `turn` function. Its input contains:

- the user input;
- the current transcript and extension-owned slots;
- committed events since its previous activation;
- its configuration, system prompt, Tool definitions, and deterministic runtime envelope.

During the activation it may call Brain's `events`, `model`, `dispatch`, `emit`, and `telemetry` imports.
`model`, `dispatch`, and `emit` cross the Brain boundary. Brain commits an external-effect intent
before dispatch, sends it once, and commits its terminal or unknown outcome before returning it.

The Component returns the transcript and slots to keep. Brain journals their changes; every turn uses a fresh Wasm
instance, while compiled and prelinked code is reused.

## Placement and capabilities

`brainWasm(...)` is Brain's built-in Component Environment. It creates a fresh Wasmtime instance
per activation and exposes only the capabilities selected on that Environment:

```ts
const isolated = brainWasm({
  network: { allow: ["https://models.example.com"] },
  filesystem: { workspace: true },
  secrets: ["COMPACTION_KEY"],
});
```

The current server executes Agentloops only in `brainWasm(...)`. The factory still requires an
explicit `env` so the placement is sealed into the session instead of inferred. Brain does not
fall back to another placement after failure.

## State and failures

The transcript and returned slots are the Agentloop's durable state. Host memory, open connections,
and files are not. An activation interrupted by restart is recorded as failed and is not replayed.
The next turn rebuilds its inputs from the canonical journal.
