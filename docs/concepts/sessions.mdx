---
title: Sessions
description: Send messages, read a conversation, follow progress and stop work.
---

A session is one conversation and the work the agent does for it. It keeps the model and tools
you selected, the messages, tool results and progress. Save its ID to open it again later.

The [quickstart](/brain/docs/quickstart) creates a session. The examples below use that
`brain` client and `session` before ending them.

## Send messages and read the answer

```js
await session.send("Where is order A-1001?");
await session.send("Summarize that in one sentence.");
const { messages } = await session.transcript();
console.log(messages);
```

Each message starts a turn: the agent can call the model and tools before it finishes.
`send()` waits for the turn and returns session state. The Agentloop chooses its answer;
your application decides how to present or validate it.

## Read progress

```js
for await (const event of session.events()) {
  console.log(event.sequence, event.type, event.data);
}
```

`events()` reads saved history and finishes. `stream()` follows live output; start it before
sending a message when you want to display progress as it happens. Save the last event sequence
and pass it to `events(after)` or `stream(after)` to catch up after reconnecting.

## Submit work and come back later

```js
const sequence = await session.submit("Summarize the conversation.", {
  idempotencyKey: "summary-1",
});
console.log({ sessionId: session.id, sequence });
```

`submit()` returns once Brain has saved the request. Work on the server can continue after
the client closes. Tools in `hostEnv` still need their application process connected.
If you lose the response, repeat the same submission with the same key.

In another client, open the session with `await brain.sessions.get(sessionId)`, then read
its events and transcript. `await session.outcome(sequence)` reports whether that specific turn
is pending, ended or failed, including its terminal event and any assistant answer. To use application tools after an application restart, follow
[host reconnection](/brain/docs/reference/tool-contract#reattaching-after-restart).

## Stop, finish or delete

| Call | Effect |
| --- | --- |
| `session.interrupt()` | Stop the current turn and unfinished tools; allow later messages |
| `session.end()` | Finish the conversation and keep its history |
| `session.delete()` | Delete an ended or failed session and release its environments |
| `brain.close()` | Close this client's connections; keep stored sessions |

Cancellation does not undo actions a tool has already taken. Brain preserves saved history
after a server restart, but reports interrupted work as failed. It never automatically replays
an uncertain action. Keep backups for protection against storage loss.

See [history and recovery](/brain/docs/reference/session-history) for exact event, delivery
and durability behavior.
