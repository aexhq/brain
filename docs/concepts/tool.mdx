---
title: Tools
description: Typed capabilities implemented in the application or placed in an Environment.
---

A Tool is the model-visible contract for one action: a name, description, input schema, and
optional output schema. Its implementation is either resident in the application process or
placed in an Environment. The two forms use the same session and journal semantics.

## Resident Tools

Use `run` when the function already lives in the application creating the session:

```ts
import { tool } from "@aexhq/brain";
import { z } from "zod";

const lookup = tool({
  name: "lookup",
  description: "Look up one item.",
  input: z.object({ id: z.string() }),
  options: z.object({ prefix: z.string() }),
  run: async ({ id }, ctx) => {
    await ctx.emit("lookup_started", { id });
    return { value: `${ctx.options.prefix}${id}` };
  },
});

const bound = lookup({ prefix: "item:" });
```

Calling the factory binds the options. With no options schema, call it as `lookup()`.

The SDK registers one resident host with Brain and consumes its command stream over SSE. A command
contains the session, committed journal sequence, deadline, and Tool invocation. The host validates
input and output, runs the function, and posts one outcome. `ctx` contains `options`, `callId`,
`deadline`, `signal`, and `emit`. Awaiting `ctx.emit(kind, data)` waits until Brain has committed the
extension event.

Resident code has the ambient authority of its application process. No Environment is on that
execution path.

## Placed Tools

Use `implementation` when an Environment executes the Tool:

```ts
import { brainWasm, component, tool } from "@aexhq/brain";
import { z } from "zod";

const inspect = tool({
  name: "inspect",
  description: "Inspect one workspace path.",
  input: z.object({ path: z.string() }),
  options: z.object({ depth: z.number().int().positive() }),
  implementation: component(new URL("./inspect.wasm", import.meta.url)),
  needs: ["fs"],
});

const bound = inspect({
  env: brainWasm({ filesystem: { workspace: true } }),
  depth: 2,
});
```

The deployment must also include `workspace` in `BRAIN_WASM_FILESYSTEM_ALLOW`.

Placed factories always take `{ env, ...options }`. `implementation` may be a Component, an opaque
object understood by the selected Environment driver, or a function of parsed options that returns
that object. `needs` lists resource names Brain checks against the Environment's attach receipt;
`bindingNames` lists values the Environment injects without copying their plaintext into the
session journal.

A Component Tool implements [`contracts/tool/v1/tool.wit`](https://github.com/aexhq/brain/blob/main/contracts/tool/v1/tool.wit).
It receives JSON input, configuration, a call identity, and a deadline, and can emit committed
extension events through its host import.

## One execution rule

For either form, Brain durably commits `tool_call_started` before dispatch and sends the operation
once. It records `ok`, `error`, `timeout`, `cancelled`, or `unknown` before the Agentloop sees the
result. Brain never automatically retries a Tool call.
