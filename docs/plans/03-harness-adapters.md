# Harness adapter implementation plan

Status: Draft  
Releases: Pi at R0; OpenCode and Codex at R2  
Related plans: [local runtime](01-local-runtime.md), [tools](04-distributed-tools.md), [persistence](02-external-persistence.md), [research](../harness-integration-notes.md)

Expose one small Brain session lifecycle while preserving each harness's agent loop and native context. Keep the selected harness fixed; freeze model/effort/instructions and tool definitions/bindings for launch. Treat configuration as a value supplied to the adapter, so later updates need not replace the public session model. The [API plan](05-api-and-sdks.md#future-configuration-updates-proposed) proposes the update semantics. Pin upstream dependencies in the build; support only the tested integration. No compatibility matrix, protocol negotiation, or migration layer is required.

Document supported input timing, interruption, external tools, rewind, checkpoint boundaries, and portable restore. A successful append/queue response does not mean the model has consumed the event. The harness decides when to call the model, how to compact, and whether to continue after a result. Brain does not add a competing loop, model proxy, tool retry policy, or approval subsystem.

Use a shared baseline with explicit optional operations, not the smallest feature set forever. Queue input until settled work using one bounded admission path; use native queues only when their semantics match. Do not silently translate steering into queuing or interrupt/restart. Steering does not promise that the model will run while a tool remains blocked. A lack of live steering must not block inspection, result delivery, or explicit interruption.

No timer may inject model-visible heartbeats or invoke inference just to poll quiet tools or preserve provider caches. Transport keepalives and process health checks stay outside context. Disable upstream cache warming explicitly rather than inheriting user configuration. Actual tool notifications and user input still follow normal harness continuation policy.

Normalize messages, tool calls/results, available usage, session status, and errors. Keep necessary native state opaque to core code; a readable transcript is not necessarily the next model input. Progress/deltas need not become model context. A low-level completion event must not end work that the harness will continue automatically.

The baseline resume guarantee is a completed, saved turn with consistent native state. A blocked tool call is cold-resumable only after that boundary and any external reattachment pass tests. Otherwise retain the live runner, or report interrupted work after loss. Never reconstruct native context by assigning normalized messages or rerun uncertain tools. A checkpoint does not capture remote compute; tools own its continuity. Verify the next model request after restore using a recording test provider, without live provider-cache dependence.

Disable native local-execution tools and ambient plugins that bypass remote bindings. Configure supported native permission mechanisms explicitly; never auto-approve an unexpected request. If an upstream integration cannot meet this setup, fail clearly rather than silently adding Brain approvals or local execution. Adapter-specific working paths may still affect prompts and native state even though Brain has no Environment entity.

Use native APIs first, trusted adapter hooks second, and a small maintained upstream patch only for a concrete missing control. Useful seams include tool registration/dispatch, fatal-stop propagation, passive restore, or a pre-request configuration hook. Keep patches within the adapter, pin the exact dependency, and test their observable behavior. Do not fork the agent loop, edit native history behind the harness, or add compatibility shims. Remote-tool isolation and passive restore are mandatory support gates; live tool replacement and mid-tool cold recovery can remain unsupported.

Generate Go and TypeScript runner wire types from one current schema. Bound output while parsing. Process exit, malformed protocol, and Brain persistence failure halt affected execution; ordinary tool timeout/denial/unavailability is returned as tool content. Model-provider failure ends the current work according to the harness and is reported distinctly. Route diagnostics away from protocol stdout. Observer disconnect does not close the harness. Dependency changes update adapters and tests together; old-state migration is out of scope.

At implementation time use the pinned dependencies' [Pi SDK documentation](https://raw.githubusercontent.com/badlogic/pi-mono/main/packages/coding-agent/docs/sdk.md), [Pi settings](https://raw.githubusercontent.com/badlogic/pi-mono/main/packages/coding-agent/docs/settings.md), [OpenCode v2 API](https://dev.opencode.ai/v2/docs/api), [OpenCode session contract](https://github.com/anomalyco/opencode/blob/dev/specs/v2/session.md), [OpenCode warming settings](https://opencode.ai/v2/docs/warming), and [Codex App Server documentation](https://learn.chatgpt.com/docs/app-server). Upstream v2 naming is not a Brain API version. These are integration entry points; conformance tests determine which capabilities Brain advertises.
