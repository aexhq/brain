---
title: Write an agent loop
description: Drive a turn through Brain's services and build a portable agent loop artifact.
---

Install Brain and Zod, then export a named definition from your entry module:

```sh
npm install @aexhq/brain zod
```

```js
import { agentloop } from "@aexhq/brain";
import { z } from "zod";

const options = z.object({ instructions: z.string().default("Be helpful.") });

export const assistant = agentloop({ options }, (author) => {
  author.turn(async (turn) => {
    turn.transcript.push({ role: "user", content: [{ type: "text", text: turn.input.message }] });
    const { message } = await turn.model({ system: author.options.instructions, messages: turn.transcript });
    turn.transcript.push(message);
    const text = message.content
      .filter((block) => block.type === "text")
      .map((block) => block.text)
      .join("");
    await turn.reply(text);
    return turn.done();
  });
});
```

Build every named extension export with one command:

```sh
npx brain build
```

For an agent loop the output is a WebAssembly component. `brain build` bundles the module and
compiles it with [componentize-js](https://github.com/bytecodealliance/componentize-js)
against Brain's `agentloop.wit` world, with stdio, random, clocks, and HTTP disabled. Brain
runs the component in Wasmtime, so the loop has no I/O of its own: every effect goes through
the `turn` object, and Brain journals each one before it happens.

Applications import the generated factory and pass it under `agentloop`:

```ts
const session = await client.sessions.create({
  agentloop: assistant({ instructions: "Answer briefly." }),
  model,
});
```

Registration is synchronous and the turn handler is `async`. Inside it, `turn.model`,
`turn.dispatch`, `turn.append`, and `turn.reply` return promises; the loop reads like ordinary
async code, and each call completes before the next line runs. Ordinary deterministic packages
can be bundled. I/O belongs in Tools and Environments.

The loop decides what the model is told on every call. Leave `system` out and the call uses the
prompt the session was created with, `author.system`; the loop above replaces it with its own
option. Leave `tools` out and every tool the session was created with is offered; name a subset of
`author.tools` to offer fewer.

## Run tools

When the model asks for tools, hand the batch to `turn.dispatch`. Brain runs the calls in
parallel and returns every result, in the calls' order, once they are all in. Call it once per
call instead and the calls run one after another; leave a call out and it never runs. The loop
below, from [`examples/coder-brain.mjs`](https://github.com/aexhq/brain/blob/main/examples/coder-brain.mjs),
runs a full coding turn and keeps a counter in a slot.

```js
import { agentloop } from "@aexhq/brain";
import { z } from "zod";

const text = (message) =>
  message.content
    .filter((block) => block.type === "text")
    .map((block) => block.text)
    .join("");

// A full coding turn: model, tools, model again, until the model answers in prose.
export const coder = agentloop((author) => {
  const memory = author.slot("memory", z.object({ turns: z.number().int() }), () => ({ turns: 0 }));

  author.turn(async (turn) => {
    memory.turns += 1;
    turn.transcript.push({ role: "user", content: [{ type: "text", text: turn.input.message }] });
    for (;;) {
      const { message } = await turn.model({ messages: turn.transcript });
      turn.transcript.push(message);
      const calls = message.content
        .filter((block) => block.type === "tool_use")
        .map((block) => ({ callId: block.id, name: block.name, input: block.input }));
      if (calls.length === 0) {
        await turn.reply(text(message));
        return turn.done({ turns: memory.turns });
      }
      // One dispatch: Brain runs every call in parallel and reports back once, in order.
      const results = await turn.dispatch(calls);
      turn.transcript.push({
        role: "user",
        content: results.map((result) => ({
          type: "tool_result",
          tool_use_id: result.callId,
          content: result.output,
          is_error: result.isError,
        })),
      });
    }
  });
});
```

`author.slot` declares state the loop keeps beside the transcript: validated by its schema on
the way in and out, live for the turn, saved when the turn ends. Brain persists it and never
reads it.

## Failing, and being told

A loop ends a turn early with `turn.fail(code, message)`. The code is what the session's
`turn_failed` record carries, so pick one a client can act on. An error the loop lets escape
ends the turn with `agentloop_failed`.

A service call can fail too: past the turn's model-call budget, `turn.model` rejects with
`model_call_limit`; after a cancel, every call rejects with `cancelled`. Let those errors
propagate. Brain records what already happened and the turn ends with that code.

`turn.events` holds the session's records since the loop last ran. A loop that wants to know
that its last turn was interrupted, or that an environment it was using has closed, reads
them there before deciding what to do; Brain never calls the model on its own because something
happened.

The official `@aexhq/agentloop-pi` and `@aexhq/agentloop-codex` loops are this shape with the
prompt, context management, and retry policy of Pi and Codex on top.
