---
title: Write an environment
description: Connect your own runtime or workspace so Brain can run tools there.
---

An environment lets Brain run code in a service you control, such as a sandbox or browser.
You usually need only an [existing environment](/brain/docs/concepts/environment).
Write one when you need a different runtime or resource lifecycle.

## Run the JavaScript example

The [lazy workspace example](https://github.com/aexhq/brain/blob/main/examples/lazy-environment.mjs)
is a small HTTP service that echoes tool input and keeps a shared in-memory workspace.
With Node.js 22 or newer:

```sh
git clone https://github.com/aexhq/brain.git
cd brain
node examples/lazy-environment.mjs
```

It listens on `127.0.0.1:8090`. For this local example, run Brain on the same host using the
[source build](https://github.com/aexhq/brain/blob/main/CONTRIBUTING.md#setup):

```sh
BRAIN_DATA_DIR="$PWD/brain-data" \
BRAIN_ENV_WORKER="$PWD/target/debug/brain-env-worker" \
./target/debug/brain --listen 127.0.0.1:8080
```

These are Bash commands. On Windows use PowerShell environment assignments and the `.exe`
binaries. A Docker-hosted Brain cannot reach this service through its own `127.0.0.1`.

## Connect a tool

In the [quickstart app](/brain/docs/quickstart), import `environment` and replace the order tool with:

```js
import { environment } from "@aexhq/brain";

const workspace = environment({ url: () => "http://127.0.0.1:8090" });
const echo = tool({
  name: "echo",
  description: "Echo a message in the workspace.",
  input: z.object({ message: z.string() }),
  implementation: { type: "reference_echo" },
});

// In sessions.create:
// tools: [echo({ env: workspace({ name: "workspace" }) })],
```

The source-built server above uses no API token; remove `token` from the example client options.
Send `"Call echo with the message hello."` and run the app. The transcript contains the echoed
input and a workspace entry count. JavaScript needs no build step; use your normal compiler
for a TypeScript service.

Edit the example's `execute` handler to run your own fixed operation. It calls the supplied
`finish` callback before returning a receipt, so Brain knows the tool has completed.

## Python and other languages

An environment service uses HTTP and JSON, so it can be written in any language with an HTTP
server. Brain includes tested JavaScript services and a
[Python project runner](https://github.com/aexhq/brain/blob/main/examples/python-environment.mjs).
The runner itself is JavaScript; it prepares and runs Python tools using `uv` and their lockfiles.

For Python code that only needs computation and Brain callbacks, use the smaller
[packaged Python tool](/brain/docs/guides/write-a-tool#python) example instead. For other service
languages, implement the [Environment protocol](/brain/docs/reference/environment-protocol);
Brain does not supply a separate environment SDK for each language.

## Deploy and use it

Deploy the service where your Brain server can reach it. Configure its URL and credential in
the `environment(...)` factory, then create a new session with that environment. Prepare code
and dependencies before executing the tool. Define when workspaces are kept and released.

The local example does not isolate untrusted code. A deployed service must authenticate requests,
validate operations, and limit the code's access to files, secrets and the network. The protocol
reference describes setup, execution, cancellation and cleanup.

Aex hosting accepts only managed profiles granted to your account, not arbitrary environment
URLs. See [managed environments](https://github.com/aexhq/aex/blob/main/docs/environments.md).
