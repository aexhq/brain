---
title: Write a Tool
description: Declare a resident function or a placed implementation with one typed contract.
---

Every Tool has a model-visible name, description, input schema, and optional output schema. Choose
exactly one implementation form: `run` for code resident in the application, or `implementation`
for code interpreted by an Environment.

## Resident function

```ts
import { tool } from "@aexhq/brain";
import { z } from "zod";

export const lookup = tool({
  name: "lookup",
  description: "Look up one record.",
  input: z.object({ id: z.string() }),
  output: z.object({ value: z.string() }).nullable(),
  options: z.object({ prefix: z.string() }),
  run: async ({ id }, ctx) => {
    await ctx.emit("lookup_started", { id });
    return database.get(`${ctx.options.prefix}${id}`) ?? null;
  },
});

const bound = lookup({ prefix: "customer:" });
```

The function remains in this process. The factory parses and freezes options. The SDK serves calls
over its resident-host SSE connection, validates input and output, and posts the outcome. With no
options schema, instantiate it as `lookup()`.

## Component implementation

```ts
import { component, tool } from "@aexhq/brain";
import { z } from "zod";

export const inspect = tool({
  name: "inspect",
  description: "Inspect one path.",
  input: z.object({ path: z.string() }),
  options: z.object({ depth: z.number().int().positive() }),
  implementation: component(new URL("./inspect.wasm", import.meta.url)),
  needs: ["fs"],
});

const bound = inspect({ env: workspace, depth: 2 });
```

The Component implements
[`contracts/tool/v1/tool.wit`](https://github.com/aexhq/brain/blob/main/contracts/tool/v1/tool.wit).
Brain admits the raw bytes by content identity. Each invocation contains the Tool input, parsed
configuration, call identity, and deadline. The Component may call its `emit` host import to append
an extension Event, or its fire-and-forget `telemetry` import for best-effort operational diagnostics
that never enter the journal or model input.

## Driver-defined implementation

An Environment may define its own immutable implementation descriptor:

```ts
const fetchIssue = tool({
  name: "fetch_issue",
  description: "Fetch one issue.",
  input: z.object({ number: z.number().int() }),
  options: z.object({ repository: z.string() }),
  implementation: ({ repository }) => ({
    type: "http_json",
    method: "GET",
    path: `/repos/${repository}/issues/{number}`,
  }),
  needs: ["net"],
  bindingNames: ["API_TOKEN"],
});

const bound = fetchIssue({ env: github, repository: "aexhq/brain" });
```

Brain treats this descriptor as opaque. The selected Environment validates and executes it.
`needs` are checked against resource names declared at attachment, and `bindingNames` select values
the Environment factory supplies outside the journal.

## Execution context

Resident `ctx.emit` and the Component Tool `emit` import both wait for the same thing: a committed
extension Event in the session journal. Brain commits a Tool intent before dispatch, sends it once,
and commits `ok`, `error`, `timeout`, `cancelled`, or `unknown` before the Agentloop sees the result.
The Agentloop and all Tools share a turn limit of 128 emitted Events and 1 MiB across serialized
Event kinds and payloads. There is no automatic retry.
