Each option is a flag and an environment variable. Flags win.

| Variable | Flag | Default | What it does |
| --- | --- | --- | --- |
| `BRAIN_LISTEN` | `--listen` | `127.0.0.1:8080` | Address to bind |
| `BRAIN_DATA_DIR` | `--data-dir` | `brain-data` | Where journals, admitted Components, environments, and local state live |
| `BRAIN_LOOP_WORKER` | `--loop-worker` | `brain-loop-worker` | Path to the loop worker executable |
| `BRAIN_WASM_NETWORK_ALLOW` | `--wasm-network-allow` | empty | Comma-separated HTTP origins or authorities the server may grant native Components |
| `BRAIN_WASM_SECRET_ALLOW` | `--wasm-secret-allow` | empty | Comma-separated process environment variable names the server may grant native Components |
| `BRAIN_WASM_FILESYSTEM_ALLOW` | `--wasm-filesystem-allow` | empty | Comma-separated writable roots (`scratch`, `workspace`) the server may grant native Components |
| `BRAIN_API_TOKEN` | `--api-token` | none | Bearer token callers must present |
| `BRAIN_MODEL_BASE_URL` | `--model-base-url` | `https://ai-gateway.vercel.sh/v1` | Endpoint for the `vercel-ai-gateway` provider |
| `BRAIN_OPENAI_BASE_URL` | `--openai-base-url` | provider default | Endpoint for the `openai` provider, or any OpenAI-compatible server |
| `BRAIN_ANTHROPIC_BASE_URL` | `--anthropic-base-url` | provider default | Endpoint for the `anthropic` provider |
| `BRAIN_PROVIDERS_FILE` | `--providers-file` | none | JSON file of custom provider definitions merged over the catalog |
| `BRAIN_ENVIRONMENT_BASE_URL` | `--environment-base-url` | empty | Default environment adapter endpoint |
| `BRAIN_ENVIRONMENT_API_KEY` | `--environment-api-key` | none | Credential for that adapter |
| `BRAIN_ENVIRONMENT_ROUTES_FILE` | `--environment-routes-file` | none | JSON map of driver names to deployment-granted `{ endpoint, api_key? }` routes |
| `BRAIN_MAX_MODEL_CALLS` | `--max-model-calls` | `128` | Model calls one turn may make before the next fails with `model_call_limit` |
| `BRAIN_MAX_TURN_SECS` | `--max-turn-secs` | `1800` | Seconds one turn may run before it is cancelled; `0` means no bound |
| `BRAIN_SESSION_IDLE_TTL_SECS` | `--session-idle-ttl-secs` | none: release after each turn | Seconds an idle session keeps its task and memory before it is suspended to disk; a session may set its own at create; `0` means never |

## The data directory

Brain owns everything under `BRAIN_DATA_DIR`. Its only format is `brain-data/1`, replaced in place
during pre-launch development. Start with an empty directory; Brain writes its format marker on
initialization. There are no legacy layouts or migrations.

```
brain-data/
  .lock                               process-held single-writer lock
  format                              layout marker (`brain-data/1`)
  sessions/{session_id}/journal/      one canonical journal per session
  sessions/{session_id}/checkpoint    disposable current-state/index projection
  environments/{environment_id}.json environment records
  agentloops/                         admitted Agentloop and Tool Components
  native-workspaces/                  workspaces for Brain Wasm Environments
  run/                                worker sockets
  server-metadata/                    model credential custody
  requests/requests.log               durable HTTP request claims and answers
  resident-hosts/hosts.log             resident host identities and token hashes
```

Session configuration, status, public Events, transcript, and Agentloop slots are projections of
the canonical journal. Brain does not keep a second event or state log.

## Listening beyond loopback

Brain refuses to start on a non-loopback address without `BRAIN_API_TOKEN`. Binding `0.0.0.0` with
no token is a mistake worth failing on rather than serving.

Brain Wasm network, secret, and writable-filesystem requests must also appear in the three server
allowlists above. Keep them empty in a multi-tenant deployment unless its control plane supplies
the corresponding tenant custody, egress, and storage boundary. Never place Brain's own API,
Environment, or cloud credentials in the secret allowlist.

## Docker

The image sets `BRAIN_DATA_DIR=/var/lib/brain`, `BRAIN_LOOP_WORKER=/usr/local/bin/brain-loop-worker`,
and `BRAIN_LISTEN=0.0.0.0:8080`, declares `/var/lib/brain` as a volume, and runs as uid 10001.

```sh
docker run --rm -p 8080:8080 -v brain-data:/var/lib/brain ghcr.io/aexhq/brain:latest
```

Immutable tags are `ghcr.io/aexhq/brain:sha-<commit>`. Pin those for deployments; `latest` is for
people.

## Health

`GET /health/ready` answers when the server is serving.

## Environment routing and expiry

A routes file maps `configuration.driver` names to endpoints and optional bearer credentials.
Each route uses a separate credential binding; session-supplied URLs never select a Brain credential.
HTTPS and loopback HTTP are supported. [`examples/environment-routes.json`](https://github.com/aexhq/brain/blob/main/examples/environment-routes.json)
shows two independent providers. The default endpoint can still serve a single gateway.

Environment resource TTL belongs in that provider's configuration. Setup and attach may be logical
operations that declare capabilities; allocation may wait until invoke. Brain neither restarts an
expired resource automatically nor promises its files will survive a restart.
